The answer came out too long. Rewrite it.

Respond in the language the user wrote in.

**Target:** your last answer. If the user pastes a text, the target is the pasted text.

## The rule that governs

**Shorten by choosing what goes in, not by compressing the writing.** Readable matters more than short — the result is a smaller answer, not a telegram.

## Cut

First, apply to the already-written text the FORM rules that arrive with every message: first line answers, no closing paragraph, no repeating what is on screen, no hedging, no self-praise.

Then these four cuts, which exist only here:

| # | What goes out |
|---|---|
| 1 | Justification for a decision nobody questioned |
| 2 | An alternative you are not going to pursue |
| 3 | The same information twice, once in prose and once in a table — the table stays |
| 4 | A table with fewer than 3 rows — becomes a list or a sentence |

## Do not cut

Facts, numbers, `file:line`, real caveats, what was left out of the work, open questions, and what the user needs to decide.

If the cut removes information, it is not simplification — it is loss. When torn between cutting a fact and being one line longer, be one line longer.

## Format

Concept before flow. Table and diagram before paragraph. Concrete example before abstract description.

## Delivery

Only the rewritten text. No "here is the shorter version", no listing what you removed, no apologizing for the previous one.
